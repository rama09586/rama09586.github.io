Data and account access

Privacy policy

Last updated October 26, 2026 · Policy version 2026-10-26

CompanionKnowWhy Publisher is operated by the CompanionKnowWhy channel owner. It runs on the owner’s computer to prepare and publish the owner’s videos. It is not a public account-management service. Questions and data requests can be sent to companionyoutube@gmail.com.

Information the application uses

The publisher uses locally supplied videos, images, captions, titles, descriptions, and publication settings. When the owner connects accounts, it uses authorization credentials and account identifiers to access the selected YouTube channel, Facebook Page, and Instagram professional account.

Through the APIs, it reads account identity, linked-account information, video processing and visibility status, and caption status. It keeps upload identifiers, completion receipts, media fingerprints, and resumable-upload state locally so it can resume work and avoid duplicate posts. The application does not ask for or store a Google or Meta account password.

Why the information is used

Account information is used to verify the intended publishing destinations. Authorization credentials are used to upload videos, apply supported metadata, thumbnails and captions, and verify publishing results. The owner supplies the videos and content settings, configures the three channel accounts, and controls whether the publishing worker runs. The current automated workflow publishes the full video and its teasers to those configured destinations.

The publisher does not sell API data, use it to target advertisements, or send it to model-training services. Account API data is not an input to its video-generation models.

Storage and retention

In this installation, credentials and publishing state are stored in a private directory on the owner’s computer, outside the source repository and cloud-synced video folder. Operating-system file permissions restrict access. Video sources and exports stay in locations chosen by the owner.

The publisher expires stored API upload records after 30 days when its commands or worker run. Expiry removes remote upload identifiers, receipts and resumable-upload sessions; it keeps local input fingerprints and retry holds so deletion does not trigger duplicate uploads. Records without a trustworthy storage date are expired conservatively. Saved credentials are kept while the connection is used. Policy acceptance is recorded locally and must be repeated when the configured policy version or links change.

This is a local application: cleanup cannot run while the computer is off. The owner must keep maintenance running while retaining API records, or use the data-deletion command before a long shutdown. Owner-created backups and copies need separate deletion. No background scheduler is installed automatically.

Sharing and platform services

The application uses YouTube API Services. Approved media, metadata and account requests are sent to Google/YouTube and Meta/Facebook/Instagram for publication. The current automated workflow requests public publication; account connection alone does not publish content. Local publishing credentials are not uploaded to this information website.

Google’s handling of data is described in the Google Privacy Policy. Use of YouTube is governed by the YouTube Terms of Service. Meta’s handling of platform data is described in the Meta Privacy Policy.

Revoke access or remove local data

The standalone publisher provides the following controls. Run each command with --config /path/to/social.yaml, using the location of your private configuration:

  • Delete data (videogen social delete-data) removes stored API publishing records and old receipt-bearing logs. It retains source media, configuration, credentials, policy acceptance, and local input fingerprints/retry holds.
  • Disconnect YouTube (videogen social disconnect-youtube) asks Google to revoke the project’s authorization grant, then deletes local YouTube credentials and YouTube API publishing records. Revocation can affect other OAuth clients and scopes under the same Google project. If Google cannot confirm revocation, publishing is held and the token is retained privately only so revocation can be retried; stored YouTube API records are removed immediately.
  • Maintain (videogen social maintain) expires old records and checks Google authorization even without queued uploads. A confirmed invalid refresh grant causes local YouTube credentials and API publishing records to be removed. Network failures are not treated as confirmed revocation.

These operations refuse to race an active upload. Stop the worker before managing access. You can also revoke Google access through Google account permissions. For Meta, remove the app through Facebook’s business integration settings, remove the local Meta credential file, and run the data-deletion command. Delete owner-managed backups and copies separately.

The channel operator can help with deletion or access requests at companionyoutube@gmail.com. Deleting local records or revoking authorization does not delete videos already published to a platform; those must be managed separately in the owner’s YouTube or Meta account.

This website

This information site does not include an account login, upload form, advertising, or analytics scripts added by the channel operator. Its hosting provider may process technical request information to serve and protect the site. Following a link to YouTube, Google, Meta, or your email application opens a separate service with its own policies.

Changes and questions

Read and accept this privacy policy and the terms before using connected-account features. This page and its version will be updated if the application’s data practices change. Contact companionyoutube@gmail.com with questions or concerns about these practices.
